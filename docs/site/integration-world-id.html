Friction points

What we already know:

  • The callback must be HTTPS. Local development needs a trusted local certificate (we use mkcert) before the web flow works at all.
  • The pairwise sub depends on the callback hostname. 127.0.0.1, localhost and a deployed domain yield different identifiers for the same person, so bans, caps and engagement ownership do not carry across them. Pick one hostname per environment.

Missing capabilities or docs

  • Nonce in the device flow. The discovery document does not state whether a nonce sent with the device authorization request is echoed back in the ID token. We send it and verify it when present; when it is absent we fall back to binding the approval to its device code on our side and record a nonce_absent event.
